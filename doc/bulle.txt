1. INTRODUCTION                                         *bulle-introduction*

bulle.nvim shows you what bulle changed in the buffer you are already editing.
Files reload when bulle writes them, edits are marked in place, and you step
through them with ]r and [r.

The cursor is never moved for you by default: bulle tells you it changed
something and marks where. Setting `follow` to "peek" or "open" makes it more
forward.

==============================================================================
2. REQUIREMENTS                                         *bulle-requirements*

Neovim 0.10 or newer, and bulle 0.76 or newer on $PATH.

The hook shim `bulle-nvim` must also be on $PATH; it is `bin/bulle-nvim` in the
plugin. Run |:checkhealth| for bulle to see what is missing.

==============================================================================
3. SETUP                                                     *bulle-setup*

With lazy.nvim: >lua
    { "FacileStudio/bulle.nvim", opts = {} }
<

When the plugin loads it calls `setup()` itself. To configure it yourself, or
to lazy-load on commands, set this first: >lua
    vim.g.bulle_nvim_no_defaults = true
<

Then call |bulle.setup()| when you want it.

==============================================================================
4. THE BULLE HOOK                                             *bulle-hook*

No bulle release offers a socket yet, so edits are reported through hooks. Add
both of these to `~/.bulle.yml`, or to a project's `.bulle.yml`: >

    hooks:
      - name: bulle.nvim
        on: after_tool_call
        match: [edit_file, write_file, run_command]
        run: bulle-nvim emit
        timeout: 2s
        async: true
      - name: bulle.nvim
        on: before_tool_call
        match: [edit_file, write_file, run_command]
        run: bulle-nvim before
        timeout: 2s
        async: false
<

`run_command` is listed because a shell command can edit a file in place, and
the plugin ports bulle's own parser for those commands. Leave it out and only
`edit_file` and `write_file` are reported.

The first hook reports an edit once it has landed. The second is what gives a
file you never opened in Neovim its line numbers: `write_file` and
`run_command` report no old text, so the plugin needs a copy of the file from
before the call to diff against. `bulle-nvim before` hands over the paths the
tool is about to touch and waits until the plugin has read them, so the tool
cannot overwrite the file first. That is why it is `async: false`: an async
hook would let the tool run before the copy was taken. The wait is bounded and
skipped entirely when no Neovim is watching, so it costs a few milliseconds
per editing call and nothing when you run bulle with Neovim closed.

`on:` takes one event per entry, so this is two entries rather than one. bulle
asks before running a hook it has not seen in a project before; that prompt is
per repository.

The shim appends one JSON line per edit to `$XDG_RUNTIME_DIR/bulle-nvim/`, which
the plugin tails. That directory is 0700 and its files 0600, because the payload
carries the text of the edited file. The plugin deletes it on startup. While it
watches, the plugin also leaves a `plugin` file there holding its pid, which is
how the `before` shim knows whether anyone is there to answer it.

5. COMMANDS                                               *bulle-commands*

:BulleChanges                                                    *:BulleChanges*
    List every file bulle changed, with hunk and line counts. <CR> opens the
    file under the cursor at its first changed line. `q` closes the list.

:BulleClear                                                      *:BulleClear*
    Forget every recorded edit and clear the marks.

:BullePeek                                                        *:BullePeek*
    Show the last edit in the current buffer in a float, without taking focus.

:BulleToggle                                                    *:BulleToggle*
    Toggle the chat pane. Opens a right-hand split running bulle, or closes it
    if it is already open. The pane has its own buffer, so it never takes over
    the file you are editing, and it opens from the dashboard too.

    Closing the pane hides its window and leaves bulle running, so toggling back
    returns to the same session. Closing it does nothing when the pane is your
    only window.

:BulleStart [cmd]                                                *:BulleStart*
    Open the pane without toggling it closed. Optional arguments replace the
    command, so `:BulleStart bulle --model opus` works. When the pane is open and
    its process has exited, this starts a fresh one.

:BulleRevert                                                  *:BulleRevert*
    Revert the bulle edit under the cursor, splicing the old text back in. It
    refuses, with a reason, when the edit carried no old text to restore, when
    the buffer has unsaved changes, when the file no longer holds the new text,
    or when that text occurs more than once and the position would be a guess.

:BulleRevertAll                                            *:BulleRevertAll*
    Revert every bulle edit in the current file in one go, and report how many
    hunks were restored.

:BulleSend [text]                                              *:BulleSend*
    Send the current selection, with the file, line and branch as context, to
    the attached bulle session. With no argument, a prompt is asked for. Needs
    an attached session over bulle's IDE socket, which a session serves only
    when bulle runs with --ide or $BULLE_IDE is set; without one this warns
    rather than doing nothing.

:BulleAsk [text]                                                *:BulleAsk*
    Like |:BulleSend|, but sends the whole buffer instead of the selection.

:BulleOpen                                                      *:BulleOpen*
    Ask the attached session to scroll its own view to the line the cursor is
    on in this file. Needs an attached session, as |:BulleSend| does.

:BulleCancel                                                  *:BulleCancel*
    Cancel the run in progress in the attached session, as Ctrl-C does in the
    pane. Needs an attached session.

:BulleAttach                                                  *:BulleAttach*
    Attach to a bulle session over the IDE socket, or resume looking after
    |:BulleDetach|. The plugin looks for a session on its own when it loads, so
    this is only needed after a detach or when the socket is off.

:BulleDetach                                                  *:BulleDetach*
    Stop reconnecting and drop the IDE socket. The chat pane and the bulle
    process in it keep running; only the event stream stops. |:BulleAttach|
    resumes it.

:BulleStatus                                                  *:BulleStatus*
    Report whether the pane is open, whether a session is attached, the root
    in use, and the last turn and tool the session reported.

:BulleHealth                                                    *:BulleHealth*
    Run the health check in the current buffer.

6. MAPPINGS                                               *bulle-mappings*

]r                                                       *]r* *bulle-next-edit*
    Jump to the next edit bulle made in this buffer. Wraps.

[r                                                   *[r* *bulle-prev-edit*
    Jump to the previous edit. Wraps.

<leader>ko                                                 *<leader>ko* *bulle-toggle*
    |:BulleToggle|: open the chat pane if it is closed, close it if it is open.

<leader>kc                                              *<leader>kc* *bulle-changes*
    |:KoriChanges|

<leader>kp                                                 *<leader>kp* *bulle-peek*
    |:KoriPeek|

<leader>kr                                               *<leader>kr* *bulle-revert*
    |:KoriRevert|

<leader>ks                                                 *<leader>ks* *bulle-send*
    |:KoriSend|

No default mapping overwrites one you already have. Check the mapping without
the plugin with |:checkhealth| bulle.

7. CONFIGURATION                                           *bulle-config*

>lua
    require("bulle").setup({
      enabled = true,
      root = nil,
      spool_dir = nil,
      follow = "off",
      keymaps = true,
      notify = true,
      reload = { enabled = true, debounce_ms = 120 },
      marks = { enabled = true, signs = true, virtual_text = true },
      notifications = { enabled = true, window_ms = 250 },
      ide = { enabled = true, dir = nil, retry_min_ms = 500, retry_max_ms = 10000 },
      ui = { panel_height = 10, term_width = 80 },
    })
<

`enabled`     Master switch. When false, no watcher starts.

`root`        Project root. Defaults to the cwd.

`spool_dir`   Where the shim writes. Defaults to `$XDG_RUNTIME_DIR/bulle-nvim`,
              falling back to `$TMPDIR/bulle-nvim-<uid>`.

`follow`      What happens when an edit lands:
                "off"   a notification and marks; nothing moves
                "peek"  a float beside the cursor with the changed lines, no
                        focus taken, closes after four seconds
                "open"  put the cursor on the first changed line. A file
                        already on screen is reached by moving the cursor
                        there; any other file opens in a window left of the
                        chat pane when one is open, and in its own tab when
                        there is no pane

              "open" never takes the cursor out of a window you are typing in,
              and chatting with bulle counts: a file still opens beside the pane
              while you type in it, you just keep the cursor. With no pane to
              put it beside, there is nowhere to show the file without
              interrupting you, so the follow is skipped until you are back in
              normal mode. A file bulle edited that has unsaved changes in a
              buffer is never followed either.

`keymaps`     Install the mappings above. Never overrides an existing mapping.

`notify`      Report bulle's progress with |vim.notify()|: attaching, each turn,
              the end of a run, and each edit. Warnings and errors are reported
              whatever it says, since a failure must not be silenceable.

`reload`      Reload a file bulle wrote, keeping the cursor and view.

`marks`       Signs and virtual text at the changed lines.

`notifications`
              Coalesce the edit notifications per file over `window_ms`.

`ide`         The client for bulle's IDE socket. `dir` overrides the ~/.bulle/ide
              directory the per session files are read from; `retry_min_ms` and
              `retry_max_ms` bound the reconnect backoff. Discovery re-runs on
              every reconnect, so a bulle started after Neovim is still found.

8. HOW IT WORKS                                               *bulle-how*

The changed lines do not come from the hook payload. The payload says which file
bulle touched; the plugin then diffs the buffer against the file on disk, which
is exact and works for any tool. The side it diffs from is, in order:

- the buffer, when it is open and agrees with disk
- the copy taken by the `before_tool_call` hook, when there is one
- the old text `edit_file` reports, spliced back into the current content

A file you never opened is therefore diffed against the copy taken just before
the tool call, and a file bulle creates is diffed against nothing, so every line
reports as added. Without the `before` hook the created-file case still works
and the rest fall back to the old text, which `write_file` and `run_command` do
not carry. That is why:

- a buffer with unsaved changes is never clobbered, and carries no marks while
  it disagrees with disk, since the line numbers would be wrong. A warning
  names the file; the marks return when you reload it.
- a file that is not open in a buffer is listed in |:KoriChanges| and receives
  its marks when you open it.

`run_command` edits are covered as far as they can be. A shell command does not
name the file it wrote, so the plugin parses the in-place edit commands bulle
itself understands (`sed -i`, `awk -i`, `perl -i`) and takes the path from
there. A command carrying real shell syntax, such as a pipe, a redirect, a glob
or a variable, is refused rather than guessed at: `sed -i s/x/y/ f.go
2>/dev/null` reports nothing, never the wrong file. A `&&` chain is refused the
same way, which in practice is how bulle often writes one, so a command like
`sed -i s/x/y/ f.go && cat f.go` is reported as nothing.

When a session is attached over the IDE socket, its events reach you with no
configuration: >

    hello      a notification naming bulle's version and model
    turn       a notification that the turn started
    tool       the |User| KoriTool event, and the last tool in |:KoriStatus|
    edit       the same reload, marks and follow a hook edit gets
    approval   the tool input verbatim, in a split, with a Yes/No dialog
    done       a notification naming why the run ended
    error      a notification at error level
<
The same events fire `User KoriHello`, `KoriTurn`, `KoriTool`, `KoriEdit` and
`KoriDone`, so a statusline or a plugin can drive itself from them. An approval
fails closed: only an explicit Yes approves, and a dismissed dialog, an escape,
an interrupt or an error is a refusal. The session's own timeout is what
decides when no answer arrives, and it denies.

9. API                                                         *bulle-api*

bulle.setup({opts})                                              *bulle.setup()*
    Configure the plugin and start watching. Called automatically unless
    `vim.g.bulle_nvim_no_defaults` is set.

bulle.statusline()                                          *bulle.statusline()*
    A statusline fragment, for example "bulle \u{25d1} 3", or "" when bulle has
    changed nothing.

bulle.changes()                                                *bulle.changes()*
    |:KoriChanges|

bulle.clear()                                                    *bulle.clear()*
    |:KoriClear|

bulle.send({text}, {whole})                                      *bulle.send()*
    Send a prompt with the current editor context attached. A nil `text` asks
    for one interactively; `whole` true sends the whole buffer rather than the
    selection. Needs an attached session.

bulle.open()                                                    *bulle.open()*
    |:KoriOpen|. Ask the attached session to scroll its view to this line.

bulle.cancel()                                                *bulle.cancel()*
    |:KoriCancel|. Cancel the run in progress.

bulle.attach()                                                *bulle.attach()*
    |:KoriAttach|. Returns whether the plugin is looking for a session.

bulle.detach()                                                *bulle.detach()*
    |:KoriDetach|. Returns whether there was an attachment to drop.

bulle.revert()                                                  *bulle.revert()*
    |:KoriRevert|. Returns whether it reverted, plus a reason when it did not.

bulle.connected()                                            *bulle.connected()*
    Whether a bulle session is attached over the IDE socket.

bulle.start({cmd})                                              *bulle.start()*
    Open the chat pane. With no argument, runs bulle. Reuses a live pane, and
    replaces one whose process has exited. Returns false on failure.

bulle.toggle({cmd})                                            *bulle.toggle()*
    Open the pane if it is closed, close it if it is open. Returns whether the
    pane is open afterwards. Closing hides the window; bulle keeps running.

bulle.is_open()                                              *bulle.is_open()*
    Whether the pane is on screen.

bulle.pane()                                                    *bulle.pane()*
    The window holding the pane, or nil.

bulle.hide()                                                    *bulle.hide()*
    Close the pane window, leaving bulle running.
